# Source development examples

These are plain-text source documents for the current ASM 0.5 plus DBG1 and
the offline source-save prototype. Nothing here opens a port or flashes a board.

- `sxb-cs-patterns.asm`: eight CS0–CS3 sequences at `$7F00/$7F20/$7F40/$7F60`.
  The owner confirms no hardware is attached to those windows. Reads only.
- `edu-led31.asm`: 31 eight-frame EDU LED animations, entry-value restoration
  on completion/Ctrl-C, and an EDU-absent return path.
- `*.numbered.txt`: enter directly at the ASM prompt; line numbers in tens.
- `*.paste.txt`: complete PASTE session including its final `.` line.
- `patterns.json`: exact named frame tables and source-buffer sizes.

Use the [workbook](../../docs/rc1/SOURCE_DEVELOPMENT_WORKBOOK.md) for the full
edit–save–assemble–debug–load–edit cycle and the
[hardware test plan](../../docs/rc1/SOURCE_HARDWARE_TEST_PLAN.md) for both boards.
The existing console/cancellation/HOLD ABI is used; direct CS/LED I/O is
explicitly annotated because this release has no public display ABI.

Generated by `tools/build_rc1_dev_samples.py`. Assembled executable S19 files
and CPU-model receipts are in `BUILD/rc1-dev-samples`. These examples add no
firmware ROM. Actual onboard-assembler output is 201 bytes (SXB) and 403 bytes
(EDU); packed editor source uses 2,514 and 5,034 bytes respectively.

All literal constants are defined at the top with `name = expression`.
`LED_CRA = $7FA1` names the EDU control register; all instruction operands
and pattern BYTE values use symbols. `Bxx` names denote literal byte values
(for example, `B80 = $80`). Numbered and PASTE companions match the masters.
EDU sources now occupy two flash sectors per saved document; SXB uses one.
The workbook PDF includes the revised source and editor line numbers.
