# Resident build contract — Phase 6

This contract describes the unchanged Phase 1–5 `asm-dev` firmware, SHA-256
`aef72be59c25f106a4ba5d0d08c0241b5e6adb0471d12d809b5025726e721be6`.
It establishes what resident ASM can build now and the preparation needed for
STR8-N modules. It does not implement a translator, resident linker, firmware
update, or whole-system self-build. No board was contacted.

The executable checks are in [test_resident_contract.py](../tools/test_resident_contract.py).
The static module/dependency inventory is produced by
[resident_module_inventory.py](../tools/resident_module_inventory.py).
[Phase 6 evidence](../tests/baselines/phase6.json) pins the source, tools, results
and unchanged prior baselines.

## Memory and input ownership

| Resource | Contract |
| --- | --- |
| Physical output | `$0200–$32FF`, exactly **12,544 bytes** |
| Packed source | `$3300–$4EFF`, exactly **7,168 bytes** |
| Symbol table | `$4F00–$62FF`, **256 records of 20 bytes** |
| State and line/token buffers | `$6300–$64FF` |
| Application zero page | `$00–$3F`; ordinary CPU stack is also used |
| Symbol spelling | **15 characters**, case-insensitive; the local leading dot is additional |
| Source text per record | **120 ASCII characters** |
| Expression depth | **8 active levels**, including the primary value: seven enclosing parentheses or unary prefixes pass, eight fail |

These ranges come from [the layout](../src/current/assembler/layout.inc) and the
verified application header: B1:`$E000`, shell entry `$E010`, 7,325-byte image,
RAM claim `$0200–$64FF`, ZP claim `$00–$3F`, valid header CRC.

A canonical source record is a little-endian 16-bit positive line number,
one-byte text length, one-byte addressing-mode cache, then text without a
terminator. Records must be sorted, numbered uniquely, and use printable ASCII
with lengths 1–120. The canonical cache is zero. Every line costs **four header
bytes plus its text**, so 7,168 is not a plain-text file-size limit. Empty lines
should be omitted from canonical documents. The editor and source-storage
validators enforce additional document rules; the callable assembler is not
a substitute for that admission validation.

The interactive reader's 120-character limit includes the typed line-number
prefix. PASTE's unnumbered source line may itself contain 120 characters. Tabs
entered through the reader become spaces. Numbered editing accepts line numbers
1–65,535; PASTE assigns numbers in steps of ten. The exact-full source document
assembles, and another editor insertion refuses without changing it.

All defined globals, constants, scoped locals and unresolved reference entries
share the 256-record budget. Imports also consume records. A local belongs to
the preceding global **label**; a global EQU does not change that scope.
`SYMS` displays names such as `PARENT.LOCAL`, but that display spelling is not
accepted as a cross-scope source reference. `.LOCAL` refers to the current scope.

## Logical address and generated bytes

`ORG` is already logical. It does not move the output buffer or write to its
target address. This unchanged source:

```asm
ORG $F000
LDA #$42
JSR $7E6D
RTS
END
```

emits `A9 42 20 6D 7E 60` into physical RAM `$0200–$0205`; its logical extent is
`$F000–$F005`. S19 exports those logical addresses, with verified S1 checksums,
at most 16 data bytes per record, and one S9 record containing the origin.
Neither assembly nor export changes modeled flash.

Before the first emitted byte, repeated ORGs may reposition freely. Afterwards,
ORG may move forward, generating contiguous fill bytes; the default fill is
zero and `ORG address,fill` selects another byte. Backward movement refuses.
Gaps consume output capacity. There are no discontiguous sections or bank tags.

The final byte at logical `$FFFF` is legal. A subsequent emission or ORG refuses;
output never wraps into address zero. A label immediately following that last
byte nevertheless has the wrapped value `$0000`. Use origin plus length as a
linear extent, potentially ending at `$10000`, rather than that label as an
end boundary. Branch displacement arithmetic is modular 16-bit and must still
fit signed eight-bit range, including branches across address zero.

S9 always contains the origin; `END entry` is unsupported. A firmware header's
executable entry can differ from its assembly origin, so the build manifest must
record the executable entry separately. For example, ASM's own header is at
`$E000` while its shell entry is `$E010`.

Successful output is not automatically executable at `$0200` when its origin
differs. The shell suppresses the default-origin Store suggestion and prints a
relocation message. That message does not authorize a ROM load. Monitor RAM
loading limits and the preserving installer remain separate checks. No emitted
ROM-address example was loaded into ROM or executed by these probes.

## Language and two-pass rules

| Supported | Details |
| --- | --- |
| Instructions | The current table contains **212 encodings / 98 mnemonics**, with 65C02 addressing forms |
| Directives | `ORG`, `BYTE`, `WORD`, `TEXT`, `FILL`, `END`, with optional leading dot |
| Definitions | `name:`, `name = expression`, `name EQU expression`, `name .EQU expression` |
| Expressions | Decimal, `$hex`, `%binary`, single-character literals, symbols, current PC `*`, parentheses; unary `+ - < >`, binary `+ -` |
| Data | WORD is little-endian; BYTE/TEXT accept strings with `\n`, `\r`, `\t`, `\0`, `\"`, `\\` escapes |
| Arithmetic | Computed values wrap at 16 bits; oversized numeric literals refuse |
| Byte values | `-128..255`; BRK signature specifically requires `0..255` |

There is no resident `INCLUDE`, `INCBIN`, `MODULE`, `XDEF`, `XREF`, section,
macro or conditional-assembly facility, object format or linker. WDC `DB` and
`DW` are not aliases for resident BYTE/WORD. Multiplication, division, bitwise
operators and shifts are unsupported. Native 816 instructions and 24-bit
operands are outside this language.

The table accepts WDC 65C02 bit-operation encodings even while ASM itself runs
on a 65C816. Syntax acceptance does not make such output safe to execute on the
816. Shared STR8-N code must retain its existing CPU-compatible instruction
selection or an explicitly tested CPU-specific path.

Assembly makes two passes. Ordinary forward instruction/label references are
supported. The first-pass addressing mode is cached so a forward address later
resolved into zero page retains its original absolute instruction width.
`<expression` truncates to the low byte and permits forced zero-page selection;
there is no direct force-absolute spelling. Constants and layout expressions
for ORG/FILL must already be defined. Redefinitions, unresolved references,
out-of-range branches and phase changes refuse. A model-only source change
between passes was rejected by the phase check.

## Result, export and persistence rules

`ASM_ASSEMBLE` is a callable **private interface for this pinned build**. Resolve
it from the verified symbol map, with ASM's bank visible and its entire RAM/ZP
ownership available. It is not a new public, reentrant API. Existing monitor
service preconditions apply: IRQ disabled, decimal clear; on 816, E=1 and direct
page, DBR and PBR zero. Caller registers and application ZP are scratch.

Provide the packed source at `$3300` and its exclusive end pointer in the
little-endian `SRC_END` field at `$6300`; valid bounds are `$3300–$4F00`, with
every record wholly below that pointer. Set `DX_LIST` at `$63C0` to zero for a
non-listing call. The monitor's RAM console/cancellation services must already
be initialized. These probes call from an initialized ASM session; placing raw
source into RAM alone does not establish the engine's execution environment.

Carry clear and `RESULT_VALID=1` indicate success. Result length and logical
origin are 16-bit fields at `$6302` and `$6304`. Carry set and the private ERROR
and LINENO identify failure. A failed second pass can leave partial output;
`RESULT_VALID=0` makes it unusable. The shell refuses S19 until a new successful
assembly. Overflow refusal is not a transactional rollback of output RAM.

Accepted source edits invalidate compiled output. SAVE/LOAD invalidate it once
their scratch/transfer stage begins; an edit refused before mutation or a LOAD
canceled at its dirty-source confirmation can preserve the prior validity.
SAVE uses output RAM as temporary storage and canonicalizes per-record mode caches to zero in AS/1
source envelopes; text and line numbers remain intact. LOAD restores source,
not an executable or symbol table. Reassemble after a source operation.
The new probes verified optional SRAM save/load and cache canonicalization,
plus safe refusal on bare configurations; earlier Phase 5 evidence covers the
broader storage/DBG workflows. No flash-source save was performed in Phase 6.

ASM has no standalone RUN command or ROM-programming command. Executing a RAM
program, saving an executable and installing firmware are separate workflows.

## Module admission contract for Phase 7

Every proposed resident unit needs a versioned manifest containing:

1. Unit name, authoritative source paths/hashes and baseline firmware identity.
2. Assembly origin, executable entry if any, and exact expected output extent.
3. Storage placement separately: bank/segment, or the enclosing embedded asset.
4. Explicit imported values, exported symbols, compact aliases and fixed ABI assumptions.
5. A deterministic source-preparation recipe, with collision and unsupported-syntax refusal.
6. Actual admitted packed bytes, line/name maxima and symbol count, including imports.
7. Expected machine-code hash, comparison against the existing link, and CPU test requirements.
8. Packaging rules for headers, CRCs, fill, records and generated includes.
9. Execution prerequisites and memory effects; byte equivalence alone grants no execution permission.

Preparation must handle WDC wrappers, includes, data aliases, colonless labels,
long public ABI names and unsupported expressions explicitly. Flattening the
whole public include would waste the source/symbol budget. Keep only declared
bindings, with reproducible aliases. Preserve instruction widths, addresses,
fill and byte order; compare resulting bytes rather than relying on syntax
similarity. Do not silently repair source quirks during preparation.

The static inventory covers **29 links from 28 main source files**. All have
host-dialect wrappers and therefore require preparation. Its estimates find
21 flattened source units over 7,168 packed bytes, nine over 256 definitions
even after unused-equate pruning, and one body over the output window. These
are labeled lexical estimates, not translated resident sources or admission
proofs. Conditional inclusion, renaming and decomposition still need actual
resident assembly and byte comparison.

| Initial candidate | Current linked body | Preparation estimate and qualification |
| --- | --- | --- |
| `batch/batch-gate` | 92 bytes, origin `$7C90` | 729 trimmed packed bytes / 11 definitions; remove wrappers and specify origin. Strongest first complete **byte-only** comparison. It calls fixed services and changes banking; it is not a standalone RAM test. |
| `version/version` | 636 bytes, origin `$6E00` | 4,631 flattened trimmed packed bytes / 64 definitions; resolve includes, long names, data spelling and boot bindings. A formatting routine is a smaller execution target with an explicit test wrapper. |
| `clock/clock` | 12,258 bytes | Fits output by 286 bytes, but estimated source is 72,747 packed bytes; substantial source/symbol decomposition remains. |
| `xip/utilities` | 22,312 bytes | Exceeds output as well as source/symbol budgets; must become smaller linked units. |

The existing resident-dialect UCHESS source is a useful fixture: 7,112 raw packed
bytes and 135 lexical definitions. Its byte-matching resident assembly was
established in Phase 1; this phase does not claim a fresh UCHESS rebuild.

Phase 7 can begin without adding ROM-origin support to firmware. It should
first prove a prepared small unit against its existing machine-code hash.
Full assembler self-replacement also needs explicit separation of executing
code, source and output; fitting the assembler's body in the output buffer does
not by itself solve self-hosting. Whole-image composition and preserving
installation remain independent gates.

## Reproduction and coverage

With the existing offline compiler and model dependencies installed:

```powershell
python -B tools/build_current.py --out BUILD/phase6-new
python -B tools/test_resident_contract.py --build BUILD/phase6-new --out tmp/phase6-probes
python -B tools/resident_module_inventory.py --build BUILD/phase6-new --out tmp/phase6-modules.json
```

All output paths must be fresh. The probe suite uses the unchanged linked
firmware, blocks serial imports and network connections, and refuses model
flash writes. The full suite runs 82 cases on each CPU in MON A/bare and MON
B/EDU, with three additional smoke cases in each complementary configuration:
**340 passed cases across eight configurations**. It checks actual encodings,
exact-limit/max+1 refusals, ROM logical origins, modular branches, S19 export,
partial-output invalidation, editor capacity and SRAM canonicalization.
The complete opcode table is inventoried statically; dynamic encoding probes
cover representative forms rather than every table entry.

The inherited harness models FT245 and optional SRAM transfer behavior, skips
the existing delay, and supplies discovery state. It does not qualify electrical
timing, physical persistence, native 816 applications or emitted 65C02-only
instructions on 816. No board identity, RAM, flash, recovery image, sampler or
operation marker was changed. Firmware sources, existing images and Phase 1–5
baselines remain byte-identical.
