# CLOCK 1.0 utility

Recorded 2026-10-06 America/Chicago. CLOCK is saved on 2512, 2205 and 2609
as a normal Bank 2 saved-program record. It uses the optional installed beta5
RTC service. RTC SRAM/EEPROM, alarms and saved-record timestamps remain deferred.

## Use

At the monitor prompt, enter `R CLOCK`. The utility displays usable UTC time
when available and presents `CLOCK>`. Enter `Q` to return to the monitor.

| Command | Behavior |
| --- | --- |
| `R` or `TIME` | Display a coherent UTC calendar only when READ reports usable time |
| `S` or `STATUS` | Display oscillator, running/calendar, backup and power-fail status; raw registers and retained outage evidence |
| `SET yyyy-mm-dd hh:mm:ss` | Validate UTC input, derive weekday, show status/evidence and requested time, then ask for `YES` |
| `HELP` or `?` | Show command help |
| `Q` or `QUIT` | Return to the monitor |

Commands are case-insensitive. SET accepts years 2000–2099, real calendar
dates, and 24-hour times. It computes Monday=1 through Sunday=7 automatically.
Confirmation must be exactly `YES` (case-insensitive); `Y`, trailing text,
Ctrl-C, Escape and overflowing input do not confirm it. Backspace edits input.
Invalid dates fail before confirmation. Enabled alarms refuse SET.

SET changes clock time and clears the chip's power-fail flag through the
managed API. Existing outage evidence is shown before confirmation and retained
by the driver in board RAM before the write. Control/trim are preserved. A
failed SET is reported without retry; use S to inspect state. Immediately after
a successful SET, the crystal may still be starting; R can check it again.
An outage capture in RAM is lost on RESET/replacement and is not a persistent log.
Raw outage fields have minute precision and no year, so the utility does not
invent a full timestamp or duration for them.

The utility follows the UTC convention used by the synchronized boards. A chip
previously set by other firmware has no timezone marker; displaying its calendar
does not establish that it was set to UTC. Backup-enabled status does not certify
battery health, and continuity is reported as unknown.

**Keep SET unused while the current drift measurement is running.** R/S/HELP/Q
preserve the settings. The [UTC sync and drift baseline](STR8N_V2_RTC_UTC_BASELINE_2026-10-06.md)
still applies to 2205 and 2609; no SET was confirmed during live CLOCK checks.

## Placement and application contract

| Part | Allocation |
| --- | --- |
| CLOCK code, strings and local buffers | 2751 bytes, RAM `$2000-$2ABE` |
| Text-pointer scratch | Zero page `$D0-$D1` |
| Saved record | B2 `$8000-$8AD6`, including its 24-byte header |
| Reserved storage sector | B2 sector 8; remaining bytes erased |
| Entry | `$2000`; normally launched with `R CLOCK` |
| RTC service | Existing B3 sector 8 and RAM `$6500-$66FF`; unchanged |

Clock and bus ownership remain with the installed service. CLOCK checks the
versioned `SV`/`RG` descriptors before RTC calls and uses the fixed public console
and HOLD entries. It supports 65C02 and 816 emulation with D/DBR/PBR zero;
native execution and IRQ/NMI callers are excluded. The client runs in RAM, and
its RTC calls preserve the caller's bank according to the service contract.
No MCP SRAM/EEPROM is used for program code or scratch.

See [kernel-rtc-api.inc](../tools/v2-rtc/kernel-rtc-api.inc) for the integrated
clock symbols and [clock.asm](../tools/v2-rtc/clock.asm) for the client example.
The separately retained phase 1 `rtc-api.inc` still describes the original
RAM prototype; use the integrated include for beta5 clients.

## Build and qualification

```text
python tools/build_v2_clock.py
python tools/test_v2_clock.py
```

Outputs are `BUILD/v2-clock/clock.s19`, `clock.bin`, `build.json` and
`test-results.json`. WDC02AS/WDCLN and the existing py65 dependency are used;
released firmware sources/images are not rebuilt.

| Artifact | SHA256 |
| --- | --- |
| Dense CLOCK image | `a78710d6af704db144bf11625f3d55c47ece3b018b8c88bc660f2b3f01b7ae76` |
| S19 transport | `e408dff806a33fb7ca79fb638226efb40c1c59221e847aae91d49827eb7043da` |
| Final complete B2 image | `9edf1f80284b55a91d114f37b7fe947094620cee92c4297e992ae7adaca55d71` |

Host machine-code tests compare 437 calendar/weekday cases against Python's
calendar, spanning every supported year, leap days, months and the year-low-byte
carry. They also cover malformed input, stopped time, missing software/device,
all caller banks, long/trailing/short confirmations, Ctrl-C/Escape, alarm refusal,
confirmed SET, control/trim preservation and capture before outage clearing.

Fresh full four-bank backups and independent repeats were taken on all boards.
`prepare_v2_clock_install.py` executes SAVE/RESTORE/label launch against each
exact backup and binds four expected bank hashes. B2 was verified entirely
erased before allocation. `qualify_v2_clock_board.py --save` compares current
flash to that backup, verifies the RAM load, tests read/status and SET refusal
or cancellation, reloads the pristine artifact before SAVE, verifies RESTORE
byte-for-byte, launches with `R CLOCK`, and reads all four banks afterward.

| Board | Hardware result |
| --- | --- |
| 2512 / COM4 / 65C02 / no EDU | Bounded `RTC error 01: bus not idle`; usable CLOCK prompt, invalid-date rejection, SET refusal before confirmation, saved-label launch and safe return |
| 2205 / COM3 / 65C02 / EDU | UTC display/status, explicit SET prompt and cancellation, invalid-date rejection, saved-label launch and safe return |
| 2609 / COM8 / 816 emulation / EDU | Same checks as 2205; separate entry-state fixture confirms E=1 and D/DBR/PBR=0 |

VIA state was preserved. Both EDU boards retained time, control/trim, backup/
power-fail status and their existing RAM outage capture. Confirmed SET is
qualified in the machine-code model; live utility tests deliberately cancel it
to preserve the drift baselines. The underlying installed SET service already
has [separate hardware sync evidence](STR8N_V2_RTC_UTC_BASELINE_2026-10-06.md).

The only flash change on each board is the new CLOCK record in B2 sector 8.
B0, B1, all remaining B2 bytes and all B3 bytes, including settings/wear,
RTC component, monitor slots, E and F, are unchanged. Saving into erased B2
required programming without a sector erase. Stored body readback, named launch
and complete final flash hashes match the modeled plan.

Owner-local transcripts, backups, exact plans, restored images and final reads
are in `output/qualification/clock-1.0-2026-10-06/{2512,2205,2609}`. The root
`acceptance.json` binds those records to the application and drift-baseline
report hashes. Vendor firmware backups remain excluded from Git/releases.
