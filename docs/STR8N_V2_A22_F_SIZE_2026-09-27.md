# 2.0a22 F-sector size optimization

This was the board-tested optimization prototype. It was promoted to
[2.0a23](STR8N_V2_A23_REGRESSION_2026-09-27.md) with a distinct version banner
and source tree.

The candidate reduces resident storage from 4,064 to **4,044 bytes**, leaving
20 bytes at `$FFCC-$FFDF` before the hardware vectors.

## Changes

- The main command prompt and flash risk confirmation share the selected-bank
  suffix and line reader. Falling directly into `V2_READ_LINE` saves 17 bytes.
- Bank 3 E protection branches to the existing protected-address exit,
  removing a duplicate three-byte jump.

The prototype changed `str8n-v2.asm` and `str8n-v2-flash.inc`; those changes
now live in `src/v2a23`. The a22 baseline and frozen RC1 source are unchanged.
The prototype banner remained 2.0a22, so its hash distinguishes it from the
historical a22 build.

The RAM worker remains 759 bytes and the RAM vector/public code 196 bytes.
Public ABI slots remain fixed. The E extension remains 1,208 bytes, but its
internal F calls must be relinked: 13 bytes change. Install the matching E/F
pair, preserving the configuration and all E bytes outside `$E800-$EEFF`.

## Validation and board preflight

The build and a22 S/R/T model suite passed. The exact-image F updater model
passed backup, installation, recovery, and mismatch rejection. The E updater
model passed installation, preservation, mismatch rejection, and cancellation.
Those updater tests used the existing test assertions with artifact paths
redirected to this candidate's evidence directory.

`tools/test_v2_a22_f_size.py` passed. It reuses the monitor/flash checks with the a22
boot model and adds risk-prompt acceptance, wrong-bank rejection, invalid
input, overflow, Ctrl-C, and Bank 3 E protection checks.

Board 2205 on COM3 responded at `B3>`. Complete B3:E/F readback exactly
matched the pre-change F image and E extension. Configuration was
`C 00 00 V 0A`. Complete Bank 2 was archived before any proposed update:
SHA-256 `d1a6d02d50fa6817fa65563225f62b1080ecc27d9fb33737159cb7973350526d`.
Its F sector contains the earlier a22 recovery image, SHA-256
`b1cdbc62db9429571a356b566931b6fdefb3c7fa991a4370a60226df380c6880`.
