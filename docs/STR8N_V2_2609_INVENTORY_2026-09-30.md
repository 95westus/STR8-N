# Board 2609 initial inventory and binary identity

Date: 2026-09-30. The owner identified COM8 as the new W65C816SXB board
2609 and pressed physical RESET during a receive-only capture. USB serial
number: `A10MPQXCA` (`0403:6001`). The EDU board was attached for this run.
Physical chip markings and flash identity were not inspected.

## Observed startup

The shipped firmware printed `W65C816SXB + EDU Kit Rev 1.0`, `W65C816S @
8 MHz [Native Mode]`, `Bank 0: 32KB SRAM + I/O + ROM`, and `Banks 08-0F:
512KB Ext SRAM`. Its startup scan reported:

| Device | Startup result |
| --- | --- |
| OLED SSD1306 at I2C `$3C` | OK |
| RTC MCP79411 at I2C `$6F` | OK |
| SPI SRAM 23LCV | OK |
| Extended SRAM 512 KB | OK |
| ADC ADS1015 at I2C `$48` | OK |
| CardKB at I2C `$5F` | OK |

The `M` command confirmed native mode and described extended RAM at banks
`$08-$0F`. `K` found CardKB at `$5F`. These are firmware reports, not
independent electrical measurements.

## WDCMONv2 binary identity and migration gate

The first WDCMONv2 probe, expecting `SXB3`, synchronized but timed out waiting
for board info. A later 30-second raw binary probe during physical RESET
received `$CC` twice. The first `$0C` board-info request had no reply; the
second returned `53 58 42 36 2C 01 00 00 C8 00 00 00`: **`SXB6`, hardware
3.00, WDCMON 2.00**. The shipped native EDU menu and WDCMONv2 binary
interface are both present. The original bridge rejected the 816 identity
because it accepted only `SXB2`/`SXB3` and stopped after the early empty reply.
The host bridge has been updated offline to accept `SXB?` and retry incomplete
armed board-info replies. Its live load path has not been tested on board 2609.

The `SXB6` response is evidence that WDC board/firmware identity tags vary;
the earlier `SXB3` assumption cannot identify every W65C816SXB. Migration
now checks the `SXB?` signature and asks the operator to confirm the physical
board model before RAM loading. The observed tag and model should both be
recorded for future board revisions.

The native menu cannot establish the four-bank image contents. The binary probe
sent only sync and board-info commands; no RAM-load, flash, or memory-read
command was sent during that probe. The physical board test of STR8-N and the
WDC 02/816 migration remain open.
The owner initially directed a stop to readbacks after the inventory. Later,
the owner allowed migration readbacks and a Bank 3-to-Bank 0 copy while
keeping Bank 2's virgin W65C02SXB image untouched. The first alpha24
installer load verified all 2,458 RAM bytes, but `$06` execution returned to
the native EDU menu without entering the installer; no flash copy prompt
appeared. A revised 816 entry uses `SEC/XCE` to force emulation mode. Its
offline build passed, and a later reset run reached the installer. The board
reported flash `BF/B5` and stock B3 FNV1A `280928EC`; the installer found B0
erased. The owner-authorized `COPY B3 TO B0` completed and reported
`B0 == ORIGINAL B3 VERIFIED` after exact whole-bank comparison. The host
closed the terminal before sending the alpha24 top BIN. B3:F was unchanged;
the installer has no B2 write path. B2 contents were not independently read.
In a later owner-authorized run, the installer reverified B0 against original
B3, received the exact alpha24 F BIN, programmed B3:F, and reported
`MIGRATION VERIFIED`. Physical RESET booted `STR8-N 2.0a24 B3 65C816` at
`B3>`. The complete `D F000 FFFF` readback matched the pinned 4,096-byte
alpha24 F BIN byte for byte, SHA-256
`43e6ee966963e1cc401986581742cc75b302cd0a02cfaf22965fe7ab8a43ec1a`.
Bank 2 was not selected or written. E-sector installation and broader 816/EDU
acceptance remain open.
