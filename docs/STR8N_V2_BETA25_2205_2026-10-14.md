# Beta25 upgrade on 2205 — October 14, 2026

Only 2205 was accessed. Its FTDI identity resolved to COM3. Inventory established
beta23 generation 32 in active MON A; both slots and F matched the registered
compact-boot build exactly. Both complete flash backups matched, as did both
128 KiB SRAM backups. EEPROM/history/EUI and RTC control/trim references were
captured; control was 80 and trim was -17 steps.

## Installed image

`BUILD/v2-beta25-b23` is beta25 generation 37 with the beta23-family compatibility
token EC670901 and the old direct slot validator at F30D. It preserves every
fixed-F entry used by the old monitor, journal entry addresses and worker/vector
identity. Both new monitor images assert the actual linked F30D address. The
core identity CRC and full artifact hashes remain separate from the ABI token.

The exact-backup plan updated ten sectors: journal C, the three MAINT sectors in
B1, the three affected display-asset sectors in B2, shared E/F, and MON B. MAINT
2.0 is committed after its complete body is verified; MON B's commit is the last
flash mutation. MON A is preserved byte for byte, SHA256
`71ddba38643f2e00c973f09ea2dc27dd2af3dac19a33ca72740dda562356b7d0`.
The saved default selects beta25 MON B. CLOCK, B0, the shared provider/journal
code and board-specific identity/offset tail remain unchanged.

Both monitors use the updated shared TIME display: local date/time and UTC
offset on one line. R CLOCK retains the detailed clock information. The beta23
monitor itself remains unchanged.

## Qualification before flashing

All corrected-image model suites passed: F-only bootstrap and all 123 journal
program interruption points, 11 monitor interruption points, bootstrap faults
and refusal checks, APPS validation, local-only TIME and detailed CLOCK,
startup FIFO handling, and MAINT storage transfers.

The exact 2205 mixed image passed A/a beta23, B/b/default beta25, RAM edit,
APPS, TIME, saved-program inventory, CLOCK and MAINT. Invalid commit, cookie and
CRC cases fall back to beta23; damaged A retains beta25 B. Both the old and new
monitor P commands validate and promote either generation. Read paths preserve
flash, EEPROM and SRAM in the model.

The exact installer rehearsal passed complete expected-bank comparison, erase
order, RAM execution, full MAINT verification before commit, no fallback-slot
mutation, and final verified MON B commit. Stale preimages and corrupt payloads
refused before any erase. Offline fixtures also exercised active MON B and the
beta24 generation-35 source. No other hardware ports were opened for those tests.

A build-staging error was caught before flashing: the new monitor had retained
the base package's F31B include. The builder now stages the profile include and
asserts the linked validator. All qualification above was rerun on the corrected
image. Two independent corrected builds produced identical firmware, bootstrap
utility and RAM-installer artifacts.
