# STR8-N v2-alpha1 boot milestone

Historical milestone at commit `0759787`. Current build tools generate
[v2-alpha2 with monitor commands](STR8N_V2_MONITOR_MILESTONE.md); use that
guide for the current branch. The alpha1 descriptions and sizes below are
retained as the boot baseline.

This is an independent development image, not a complete v2 release.
It has host execution coverage and has **not** been tested on physical
65C02/65C816 hardware. No firmware has been sent to a board by this work.

## Implemented

- One common-instruction-subset image for flash overlays 0-3. On the 816,
  execute in emulation mode with D=0, DBR=0, and PBR=0.
- Capture the entry flash bank from VIA PCR before peripheral initialization.
  Supported entry states are manual bank selection and the reset input state
  with board pull-ups. Physical reset behavior still needs board verification.
- Initialize private RAM and interrupt pointers without clearing application
  RAM at $0200-$68FF; copy the RAM handoff worker and interrupt entry code.
- Direct FT245/VIA console, compact banner showing the resident bank, line
  editing, CR/LF handling, Ctrl-C cancellation, and overflow rejection.
- `?` displays `J0-J3 ?`. `J0` through `J3` select the bank and jump through
  its RESET vector. Invalid low/erased vectors restore the resident bank and
  print `Bad vector`. No directory or payload signature is consulted by v2.
- Software prompt entry at provisional $F003 preserves installed vector
  pointers. The resident bank must already be selected; this is a jump entry,
  not a returning subroutine. Reset entry is $F000.
- Emulation IRQ/BRK discrimination, direct NMI/COP/ABORT entries, and reserved
  native interrupt entries. Native stubs only jump indirectly through their
  separate pointers; they do not interpret native interrupt frames.

No B/D/M/F/G/L/I/configuration command or autostart is implemented yet.
Unknown commands report `Unknown command`. Every reset holds at the prompt.
No flash-writing instructions or command sequences are present in this milestone.

## Build and host checks

WDC02AS and WDCLN must be on PATH. Python and py65 are required for execution
tests; the harness accepts existing `STR8_TEST_DEPS`/`PY65_PATH` locations or
the same `BUILD/v*/local/test-deps` locations used by v1 tests.
The v1.35 roundtrip test also requires its existing top-sector binary and
resident map under `BUILD/v1.35` (produced by the v1 `make programmer-bin`
target). The v2 build does not regenerate those baseline artifacts.

```powershell
python tools/build_v2.py
python tools/test_v2_boot.py
# Equivalent combined target:
make v2-check
```

Everything generated is under `BUILD/v2-alpha1`. Sources are in `src/v2`;
assembler source copies and sidecars stay in the build directory. Existing
v1 source files and v1 build artifacts are not regenerated by these commands.

Main outputs:

- `str8n-v2-alpha1-e000-ffff.s19`: dense payload for v1.35 I, range E-F.
- `str8n-v2-alpha1-e000-ffff.bin`: corresponding 8 KiB image.
- `build.json`: linked symbols, source/image hashes, size report.
- `test-results.json`: host execution results and hardware-test limitations.

The initial resident occupies 671 bytes including a 71-byte RAM worker and
48-byte RAM vector image. There are 3393 bytes free before $FFE0; the hardware
vector region occupies the final 32 bytes. These are milestone sizes, not an
estimate for the finished monitor. Native 816 execution is not emulated by
the current test harness; opcode compatibility and native stub bytes are
checked, with execution qualification still pending.

Tests execute actual linked instructions for boot in all four overlays,
all sixteen bank-to-bank handoffs, failed handoff restoration, line parsing,
software reentry preservation, and IRQ/BRK stack-wrap/register preservation.
They also execute the existing v1.35 directory-gated J0/J1/J2 path into v2
and v2 J3 back through actual v1.35 startup to its prompt. Those integration
tests bypass only v1's long delay subroutine and supply completed v1 directory
rows representing a successful installation. They do not emulate a complete
v1 flash installation or prove electrical/reset/serial timing.

## Intended board test through v1.35

1. Preserve the chosen disposable Bank 0, 1, or 2 before writing. Keep v1.35
   in Bank 3. The E-F image replaces BOTH $E000-$EFFF and $F000-$FFFF;
   sector E is erased padding, including disabled configuration at $EFF0.
2. At the v1.35 prompt, run I, select that bank and range E-F, and follow its
   existing enrollment/confirmation prompts. Send the E-F S19 when requested.
   V1 owns that enrollment; v2 does not implement or read its directory.
3. After v1 reports success, use its matching J command. Expect
   `STR8-N 2.0a1 Bn`, then `> `. Try `?`, an invalid command, and J3.
4. J3 should return to v1.35. Its existing startup behavior still applies;
   send S during its selector window to stay at the v1 console.
5. Record physical-reset selection, console timing, IRQ/NMI behavior, and
   unchanged recovery-bank contents before describing the image as accepted.
   An NMI during initial RAM-vector setup is not qualified by the host tests.

If v1 requires a full-bank recovery image for an incomplete installation:

```powershell
python tools/build_v2.py --full-bank
```

This additionally emits `str8n-v2-alpha1-8000-ffff.s19` with explicit $FF
padding below $E000. Installing it as 8-F replaces the entire target bank.
Do not substitute it for E-F when lower-bank software must be preserved.

The v1 host format validator can check an image without contacting a board:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/compose_str8n_install_s19.ps1 -PayloadS19Path BUILD/v2-alpha1/str8n-v2-alpha1-e000-ffff.s19 -PayloadStart 57344 -PayloadEndExclusive 65536 -Bank 0 -S19Path BUILD/v2-alpha1/validated-bank0.s19
```
