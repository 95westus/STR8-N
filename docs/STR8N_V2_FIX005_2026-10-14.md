# STR8N-005 F-only bootstrap candidate — October 14, 2026

`BUILD/v2-fix005` is a separate, unflashed beta24 generation 36 candidate based
on the STR8N-004/local-only TIME candidate. No serial ports or boards are used
by the build or model qualification.

The fixed recovery update previously requested an erase even for a fully
erased target. A missing wear journal correctly blocked that erase, leaving
F-only installations unable to bootstrap a monitor.

The candidate retains the usual image/ABI/core-cookie checks, active/preferred
slot protection and generation checks. If the journal is valid, the existing
erase-accounting path is unchanged. If there is no valid journal, every byte
of C/D must first be erased. The whole target is analyzed against the verified
upload. It can be programmed without erase only when each byte is erased or
already equal; equal bytes are skipped. This also resumes a matching partial
upload without programming any byte twice. Foreign C/D data or differing
target bytes refuse. The complete slot body is verified before the final
commit byte makes it bootable.

## Operator path from otherwise erased flash

1. Program only this candidate's B3 F sector using the normal external
   programmer procedure. Preserve its hardware vector tail.
2. At `REC>`, enter `U A` (or `U B`), confirm `Y` then Enter, and transfer the
   matching raw 4096-byte generation 36 slot binary. Successful commit restarts
   into the normal monitor. A truncated raw transfer can be abandoned by
   physical RESET; Ctrl-C is a valid binary byte, not an in-band cancel.
3. Enter `L` and send `bootstrap/bootstrap-journal.s19`. After the loader
   returns to B3, enter `G 2000` and confirm `Y` then Enter at the utility's
   `INIT blank journal?` prompt.
4. Run `W` to check all 32 counts, then `J3` to restart with the established
   configuration. Counts start at this explicit provisioning, not at the
   board's manufacture or previous unknown erase history.

The RAM utility creates the known sequence-1 record with default settings and
zero counts. It refuses a different core, another journal format, existing
wear history, non-prefix initial data, or any nonblank tail in C/D. Its own
exact interrupted byte-programming prefix can resume after RESET and reloading
the same utility. Equal bytes are skipped, all body/reserved bytes are checked
before commit, and a complete identical initial record is idempotent. It never
erases a sector. Unknown/corrupt journals require explicit external repair;
this utility does not silently replace them. Loading the utility uses its RAM
range $2000-$221C.

This path establishes a monitor and journal. F-only installation does not
contain the separate E extension, RTC/SPI components or saved programs; those
remain part of a complete firmware installation.

## Image boundaries

F uses 4056/4064 code bytes. To fit the guarded path while preserving every
existing J entry/CRC and shared F application route, `W` keeps all 32 labeled
count rows but omits its redundant title, and the missing-journal text is
shortened to `JOURNAL INVALID`. Private RAM worker addresses and bytes remain
unchanged. A/B receive the matched generation/core cookie; MAINT's four-byte
core guard is rebound. E, RTC/SPI, storage, CLOCK and TIME/status assets are
unchanged from the 004 candidate.

## Qualification

All six instruction-model suites and the exact-artifact audit pass:

- `test_v2_fix005.py`: F alone to A or B; actual S19 L/G provisioning;
  W/D/J3; all-C/D guards, invalid/incompatible/canceled uploads, six truncated
  transfers and 11 slot power cuts. Every one of the 123 journal byte-program
  cut points resumes after a cold reset and utility reload. Commit ordering,
  idempotent retry, preservation and subsequent ordinary erase accounting pass.
- `test_v2_fix005_faults.py`: wrong-slot uploads; slot/journal timeouts and
  matching retry; body corruption before journal commit; foreign core/history;
  saturated count/sequence, active-slot and stale-generation refusals.
- `test_v2_fix004.py`: native APPS corruption/validation regressions, including
  monitor A/EDU ON and monitor B/EDU OFF.
- `test_v2_time_local.py`: one-line TIME, failure paths and detailed R CLOCK.
- `test_v2_startup_fifo.py`: bounded drain, stale/fresh key handling and RAM edit.
- `test_v2_storage.py --maint`: matched MAINT guard, flash/SRAM transfer,
  refusal, short writes and timeout preservation.

The candidate's `qualification-summary.json` binds these six receipts, exact
firmware/asset/utility hashes and build/test sources. A repeated build produces
identical binaries. Python syntax and Git whitespace checks pass. No boards
were accessed or flashed. STR8N-005 remains open until physical qualification
satisfies its close criteria.
