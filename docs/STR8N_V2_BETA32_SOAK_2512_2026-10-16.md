# Beta32 enhanced preserving soak on 2512

The user requested an enhanced soak **until stopped**. This is a powered
functional/retention exercise of beta32 B, generation 44, with beta28 A kept
as fallback. It is separate from completed installation qualification,
the historical four-board beta23 matrix and electrical power-cut testing.

Runner: `tools/run_v2_beta32_soak.py`. It selects only USB serial A10MQFLCA
(board 2512, last COM4), closes the port between short leased units and yields
to pending RTC acquisition. No other board is selected. The process inhibits
idle sleep while running and publishes atomic status and per-unit reports.

## Repeated coverage

Each complete cycle has 27 units, in this order:

1. Read all four 32 KiB flash banks and compare SHA256 against exact
   post-install readbacks. This includes both monitor slots, all firmware,
   the wear journal, the opaque B0 image and the erased/free B1 bank.
2. Read all 128 KiB SPI SRAM in sixteen 8 KiB blocks and compare every byte
   with the qualified retained image, including CLOCK/CLK, directory and
   workspace. The RAM client and all device requests are read-only.
3. Read EEPROM 00–7F, FF and F0–F7 twice, checking probe completion and the
   qualified bytes, including outage history and factory identity.
4. Launch saved CLK through native SRAM; check CLOCK 1.9, running/backup
   status, unchanged control/trim (80/0C, -12), outage history and unbound
   EUI; validate the UTC calendar and require it to advance between cycles;
   query battery status without changing its record.
5. Exercise VERSION, TIME, APPS, T, M1, W and C; verify board name, offset,
   slot generations and absence of spurious boot messages.
6. Launch/query/quit all four native utilities, alternating bare aliases and
   R compatibility across cycles.
7. Exercise all-four-utility BATCH handoffs, saved CLK STATUS/Q, error stopping,
   Esc cancellation at a real confirmation prompt, and NAME refusal with NO.
8. Test CPU RAM $0200–$02FF with 00/FF/AA/55, eight walking-one patterns and
   an iteration-dependent ramp. Back up twice, publish original bytes durably
   before writing, restore in finally and verify restoration.
9. Use J3 to restart; verify default beta32 B and exactly one FLASH wear line
   with the qualified maximum: B2:8, 581 tracked erases.

Every unit checks the active monitor, EDU ON/service ABI, saved profile and
SRAM write-protection latch before and after. Flash/SRAM/EEPROM mismatches,
protocol failures and failed RAM restoration stop the run and retain evidence.
An unavailable/busy port waits without sending commands or recording a pass.
The next complete cycle repeats every retained-byte comparison; the 30-second
inter-cycle pause and shared lease allow approved RTC collection to proceed.

## Preservation and limits

No flash erase/program, SRAM format/allocation/data write, EEPROM write, RTC
setter/ACK/CLEAR, trim/offset/name change, fallback selection, or arbitrary
saved program execution is included. B2:8/9 are firmware in beta32 and must
never be reused as the older R/S/T soak's scratch sectors. Wear should remain
unchanged. CPU application RAM is borrowed for reviewed read probes and CLK;
only the explicit $0200 pattern-test window is backed up/restored by this run.
J3 invalidates volatile workspace handles. Stored workspace bytes are retained.

This checks powered operation, data consistency and software restart behavior;
it does not measure coin-cell capacity, electrical power retention, endurance
to failure or interrupt every physical program operation. Elapsed duration and
completed cycles must come from reports, not the configured start time.

## Operation and evidence

Launch from the repository with the qualified owner-local BUILD and retained
evidence present, using the bundled Python and required serial dependencies:

```text
python tools/run_v2_beta32_soak.py --root output/qualification/beta32-enhanced-soak-2512-2026-10-16
```

Default is unlimited; `--cycles 1` is a bounded smoke run. A new root is
required for each run so old passes cannot be mistaken for fresh evidence.
Create a file named `STOP` in that root to stop between units. Let any active
unit restore its RAM window and close COM4; do not kill a process mid-restore.
The root contains `config.json`, `status.json`, serial JSONL logs, numbered
unit reports, startup transcripts and any RAM `restore-state.json` recovery
record. Raw board images remain in ignored owner-local evidence, outside Git.

The installed baseline is pinned by build SHA256
`cf900395e0fde8ab5ea519b30483ab27b2f847b53755361b6f42799d74a3c052`,
the hardware receipt and its evidence hashes. The runner audits those files
and both read-probe binaries before opening a port. Host tests cover short
RAM writes, restoration failure/recovery records, flash mismatch cleanup,
bounded SRAM reads and BATCH completion/line boundaries. Start/progress is
confirmed from live `status.json`; this document alone is not a soak result.
