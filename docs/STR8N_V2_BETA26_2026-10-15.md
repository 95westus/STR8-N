# Beta26 on board 2609 — October 15, 2026

Beta26 promotes the combined battery-age and flash-wear maintenance features.
It uses generation 38 and the existing beta25 ABI family. CLOCK remains 1.8,
MAINT remains 2.1, and the fixed F image is unchanged. Monitor text changes from
2.0b25 to 2.0b26 without changing monitor code layout or public entry addresses.

Build with `tools/build_v2_beta26.py`, after the maintenance candidate's
hash-bound qualification. The separate package is `BUILD/v2-beta26`.
The builder preserves all qualified maintenance assets and rebuilds both
monitor templates with valid generation-38 headers/CRCs. Its RAM installer
uses the existing mixed SR/MI commit selector: SR byte 3 commits with 3F;
monitor byte 31 commits with 00.

## Maintenance behavior

- Battery installation date and configurable warning/replacement thresholds
  are managed through CLOCK BATTERY. Defaults are 12/24 30-day months, with
  persistent warning/uncertainty levels. Unknown age is never automatically
  initialized to the upgrade date.
- Flash warnings use the highest individual sector's recorded erase attempts:
  50,000 requests a backup and replacement planning; 80,000 requests a backup
  now and replacement soon. Counts cover tracked attempts since provisioning;
  earlier/direct operations remain unknown. W retains the detailed hex counts.
- Flash warnings work with EDU OFF; OFF performs no RTC/SPI access and retains
  its reclaimed application RAM. The reminders consume no new flash sector.

See the [battery contract](STR8N_V2_BATTERY_2026-10-15.md) and
[flash-wear contract](STR8N_V2_FLASH_WEAR_2026-10-15.md) for persistence and limits.

## Qualification correction

The exact-image beta26 boot test found that VERSION selected the battery
helper in the unflashed maintenance candidate. The range-selection branch
tested flags changed by LDY instead of the command-kind comparison. The fix
repeats CMP #5 immediately before BEQ. The shared loader is 237/254 bytes;
its fixed entry table remains unchanged. The existing VERSION instruction-model
suite is now mandatory for maintenance-candidate installation, including
default/manual slots, EDU OFF, bank changes, corruption refusal and TIME.
This defect was found before any beta26 flash write.

Beta26 also separates VERSION (service kind 7), the maintenance boot helper
(6) and the existing AUTO finder (5). AUTO's B2 reservation is extended through
DFFF so it cannot return erased helper padding or the rest of the shared
firmware sector as application storage. The actual service is tested for both
a permitted erased extent and no-space refusal with only firmware padding left.
Status remains 2,548/2,558 bytes and the shared loader 237/254 bytes.

## Board-specific installation

The target is USB serial A10MPQXCA, board 2609 on COM8. Initial state was beta25
generation 37 in B; A held beta24 generation 35. The requested installation
preserves B byte-for-byte and installs beta26 into inactive A. The saved default
becomes A generation 38. The new shared assets are compatible with retained B.

Owner-local evidence is under:
`output/qualification/beta26-2026-10-15-retry/2609/`.
The initial sandboxed COM8 attempt made no board writes; hardware access and
subsequent backup were performed through the approved execution path.

Before programming, all four flash banks were read twice and matched exactly.
The entire 128 KiB serial SRAM was also read twice with identical contents.
RTC/EEPROM references confirmed running UTC, backup enabled, control 80 and
calibrated trim 0E (-14), with no pending power-fail event. No clock setting,
trim change, EEPROM write or SRAM array write was requested.

`tools/deploy_v2_beta26.py prepare --root <board-evidence>` validates the
twice-verified backup and exact registered shared baseline, preserves the
active beta25 B slot and board-specific identity/name/offset tail, accounts for
all erase attempts, and emits an eight-sector backup-bound RAM installer:
B3:C wear/configuration; B2:D helper/status tail; B3:E shared loader; B2:C
status prefix; B1:D/C/B CLOCK continuations/header; B3:A monitor last.
Neither B0 nor fixed F is rewritten. CLOCK and monitor commit bytes remain
unwritten until their complete contents are verified.

The exact installer is checked with `tools/test_v2_unified_migration.py` against
the complete physical backup, including stale-preimage and corrupt-payload
refusal and final monitor-commit instrumentation. `tools/test_v2_beta26.py`
checks actual beta26 A / beta25 B startup, VERSION/TIME/CLOCK/BATTERY/history/
identity/W/APPS preservation and automatic fallback for invalid beta26 slots.
Both qualification receipts are required before `deploy_v2_beta26.py install`.

The RAM installer halts after device verification for a physical RESET.
`deploy_v2_beta26.py verify` captures that startup, checks default A, compares
all 131,072 flash bytes against the planned result, and queries VERSION, TIME,
CLOCK, BATTERY and W. Retained device/SRAM post-checks complete the separate
preservation evidence.

Board 2609 was flashed and physically reset successfully. Beta26 generation 38
started from default slot A, with beta25 generation 37 retained in B. The
complete 131,072-byte post-reset flash readback matched the planned image in
all four banks. VERSION, TIME, CLOCK, BATTERY and W checks passed. The battery
date remains unknown, as intended; the upgrade did not invent a replacement
date. Evidence is in `upgrade/post-reset-report.json` and `upgrade/boot.txt`
under the board evidence directory above.

Final preservation checks passed: the entire 128 KiB serial SRAM matches its
pre-install archive byte-for-byte. RTC remains running with backup enabled;

The combined hardware receipt is
`BUILD/v2-beta26/hardware-qualification-2609.json`, referencing the separate
