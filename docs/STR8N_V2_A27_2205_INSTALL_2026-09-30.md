# Alpha27 installation on board 2205 with EDU

Board 2205 is a W65C02SXB on COM3, FT245 serial `A10MPUPNA`, with the EDU
attached. Its live monitor was a26, with autostart disabled and two valid
EEPROM settings copies. Two independent 8 KiB E/F readbacks matched the
canonical a26 image, SHA-256
`62656ba960292c11104d15457b1a0ddb5480011eacdffd7fa1b3079d981127ae`.

The guarded a26-to-a27 RAM updaters passed their flash-model checks for exact
preimages, E/F order, write verification, cancellation, refusal, and B0/B2
preservation. E was installed first and verified on the board; its host
readback matched SHA-256
`ff986fdb6b64fdac2968c78eb6c8e09fcd8fdc5c15a8cf5ccd1bc47de51e6bc9`.
F was then installed and verified. The full E/F host readback was byte-exact
for the canonical a27 image, SHA-256
`d64bb6738d13690d9a12f66ea248c89cb838de947c06203301d5e41fc8f40fc1`.

Software reentry displayed the new I2C grouping:

```text
STR8-N 2.0a27 B3 65C02
ABI 65C02 | 816E | 816N-VEC
EDU KIT       DETECTED
  I2C         READY
    MCP79XXX
      RTC     $6F  Wed 26-09-30 21:13:33
      SRAM    $6F  64 BYTES
      EEPROM  $57  VALID
        AUTOSTART  DISABLED
        TARGET     B3 $F007
        DELAY      1.0 SEC
B3>
```

`C` reported `C 00 03 F007 0A`: the a26 EEPROM settings survived the flash
update unchanged. The SRAM line states the mapped capacity; no SRAM contents
were read or written. Host RTC, EEPROM, monitor, flash, load, and interrupt
regressions passed. Serial transcripts, installer receipts, and full readbacks
are under `BUILD/board/a27-2205/`.

A receive-only physical RESET window captured no startup bytes. The verified
startup and saved-settings checks above used software reentry (`G F007`).
