# W65C02SXB board 2205: alpha24 unified installer, no EDU

Date: 2026-09-30. Port: COM3 at 115200 baud. Physical board: W65C02SXB,
without the EDU daughterboard. Owner-local captures and BINs are under
`BUILD/board/2205-a24-unified/` and are excluded from the release ZIP.

## Stock baseline prepared

The board initially booted `STR8-N 2.0a24 B3 65C02`. A complete 32 KiB
readback of Bank 0 matched the previously recorded stock WDCMONv2 Bank 0
SHA-256 `2f0000c74eceec809a814e31f822702977d7bfed5ee6f3bc4869627864ca59a8`.
Its FNV-1a was `1249E1F3` and RESET vector `$F818`. The pre-restore Bank 3
was also captured (SHA-256
`a5df8348c8aa9d6d8b702c78459e3e572041823642049d513a3de8b70a10c26e`);
its F-sector SHA-256 matched the alpha24 package BIN.

A RAM factory-restore image was linked with the unified `SEC; $FB; SEI` entry
and `W2I_RESTORE_STOCK=1`. The final S19 occupied `$2000-$2CE7`, carried an
entry of `$2000`, and had SHA-256
`066326f7398831d1831d421df4f6753a04cfa4f99e90692322fc8da32f8782cf`.
All 3,304 loaded bytes matched a monitor RAM readback. At `G 2000`, it
reported `BF/B5`, source FNV-1a `1249E1F3`, and RESET `$F818` before the
explicit `RESTORE FACTORY BOARD` confirmation.

The confirmed restore copied and verified Bank 0 to Bank 3, then erased and
verified Bank 0. It reported `B0 == B3 WHOLE BANK VERIFIED` and `FACTORY
BASELINE VERIFIED: B0 ERASED; B3 STOCK`. The stock W65C02SXB EDU-demo menu
then booted. Its peripheral `OK` scan text is not evidence of EDU presence;
the daughterboard was absent.

## Alpha24 migration

The rebuilt ZIP contains the unchanged unified RAM installer S19 (SHA-256
`66bd1030c2f48444826f03562886fc4828d4047f36d4ba42d1e5f8e5396cbebe`),
whose `$FB` entry byte is a one-byte NOP on W65C02S and XCE on W65C816S.

The initial identity windows timed out while startup text queued ahead of the
binary reply. The host gate was paced and rebuilt without changing the RAM
installer S19. The final physical-reset gate returned `SXB2`, hardware 3.00,
WDCMON 2.00. The owner-confirmed physical type was `W65C02SXB` before any RAM
write. All 2,460 installer RAM bytes read back exactly from `$2000-$299B`.
The installer reported flash `BF/B5` and stock B3 FNV-1a `1249E1F3`. It
copied B3 into erased B0 and reported `B0 == ORIGINAL B3 VERIFIED`.

The host sent the packaged 4,096-byte F BIN once with Ctrl+U. The prompt
displayed lowercase `2.0a24`; the typed uppercase
`INSTALL STR8-N 2.0A24` was accepted. The installer reported `MIGRATION
VERIFIED; PRESS PHYSICAL RESET`. Physical RESET booted
`STR8-N 2.0a24 B3 65C02` at `B3>`.

Independent monitor readbacks then matched:

| Region | SHA-256 | Result |
| --- | --- | --- |
| B3:F, 4,096 bytes | `43e6ee966963e1cc401986581742cc75b302cd0a02cfaf22965fe7ab8a43ec1a` | Exact packaged BIN |
| B0, 32,768 bytes | `2f0000c74eceec809a814e31f822702977d7bfed5ee6f3bc4869627864ca59a8` | Exact saved stock image |

The packaged static bank-maintenance S19 loaded with entry `$2000`. Its
read-only `M` command mapped all four banks; `Q` returned to the alpha24
`B3>` prompt. No bank-maintenance copy or erase was requested. After a cold
power cycle, COM3 responded to CR with `B3>`; the receive-only capture did
not record the startup banner, so this is a post-cycle prompt check rather
than a captured cold-start banner.

The owner-local raw migration transcript has SHA-256
`3a61779e7e20cd06d4e9ed5a2738902c0b47f7f5fc3858a2ec0b27bc21501522`;
its event log has SHA-256
`8c01c65cad145a0004c921fc09e24cc638124cf7260a425e842da83c5d0cd32f`.
This run qualifies the unified WDCMONv2 installer and no-EDU 02SXB migration.
It does not test EDU presence, RTC, SPI SRAM, crypto, or the optional E-sector
S/R installation.
