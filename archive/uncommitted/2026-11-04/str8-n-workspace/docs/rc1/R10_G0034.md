# RC1 g0034: recovery fixes on current RC1

The boot header is **`STR8-N 2.0rc1 g0034 B3 65C02`** or **`... 65C816`**.
`g0034` is **hexadecimal**, corresponding to the full monitor generation
`00000034` (52 decimal). `VERSION` prints the same header, each slot's full
generation and `Build: rc1-r10p2-current`. Distribution is RC1 r10, patch 2.
Use a new generation for each accepted firmware change; keep the manifest and
build hash with that generation. Distribution-only revisions do not change the
firmware generation.

This is the F recovery correction applied to the **current RC1 code on
2604/2609**, whose exact baseline hash is
`c85c4055eac41e5e522f1bc62f2bd354957018e3afc1ccdc25a91e52a55a980e`.
It preserves their later monitor/ASM features. It supersedes the earlier
release-v1g-based approach for these boards. The distinct generation-51 build
previously installed on 2512 remains separately recorded in [the earlier result](R10_RECOVERY.md).
2512 has now been updated to this same g0034 firmware.

## Firmware change

- Fixed-F recovery echoes text, accepts CR/LF/CRLF command and confirmation
  lines, and reports syntax, slot protection, confirmation, image/generation,
  accounting and flash failure reasons.
- The monitor banner uses a four-digit hexadecimal generation. VERSION's build
  identity and MAINT's bootstrap-contract check are synchronized.
- The current assembler, source-storage extension, debugger, CLOCK and
  dispatcher bytes are retained. Monitor code is relinked with the banner;
  its public/internal debugger entry points remain fixed. The shared CRC
  addresses stay `$FAB4/$FABD`.
- Bootstrap contract is `$52313032`; fixed-F has 14 free bytes below hardware
  vectors. Recovery raw uploads still wait for `SEND 4096 BIN` and preserve
  every byte. The terminal's complete line ending must precede that prompt.

Reference firmware SHA256:
`0df4a802d618c0df5e658dcf2cd05037f0a892a209abaeac6bca0d595c468945`.

## Offline qualification

The corrected build has passed:

- 158 recovery CPU checks on 65C02 and 65C816 E=1.
- Full debugger and both-slot boot regression: 21 / 24 groups respectively;
  512 decoder cases on each CPU and 177 direct 816 instruction comparisons.
- Current ASM features on both CPUs and both slots: EQU, scoped lookup,
  listing/symbol output, diagnostics, storage and editing.
- ASM/DBG BS, DEL and CSI Delete behavior in both slots and both CPUs.
- Four actual monitor-banner CPU checks, including the exact `g0034` spelling.
- Independent byte-identical rebuilds.
- Six linked-installer rehearsals for **each board's own repeated capture**:
  successful install, stale-source refusal and corrupt-transfer refusal on
  each CPU. 2604/2609 each needed nine sector transfers/erases; 2512 needed 16
  from its earlier generation-51 build. These are durably reserved in each
  board's wear journal. B0, owner RAM/settings and RTC/TZ flash are preserved.

The editor-only banner fixture mocks provider discovery; VERSION routing is
checked on the live boards. Native applications/debugging, new endurance soak
and electrical power-loss atomicity are outside this bounded qualification.
