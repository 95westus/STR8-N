# Beta34 / ASM 0.5 on 2512

Flash installation, J3 restart, utilities, Microchess S/T/R and all final
data-preservation checks passed. COM4 is released. The soak remains stopped.

Board 2512 (COM4, USB A10MQFLCA, 65C02) now boots monitor B, beta34,
generation 46 (`0000002E`). Beta28 A generation 40 remains valid. The RAM
installer returned to the monitor and J3 was used for the requested restart;
no physical RESET was required.

## Assembler and saved programs

ASM 0.5 runs from B1:E000-F96B, using 6,508 bytes in the same two-sector
allocation. This adds 264 flash bytes, without changing permanent RAM
reservations or the $0200-$32FF code window. It reports:

```text
OK 1439 bytes, origin $0200, buffer $0200
RAM $0200-$079E
After QUIT; change bank/name as needed:
S 1 AUTO 0200 079E PROGRAM
```

The attributed Microchess source was entered through the actual on-board
PASTE reader and assembled. The output bytes matched the sealed example,
the game displayed its board/copyright and returned with Q. Its printed
Store command was used with UCHESS as the name. RAM was deliberately cleared
before Restore-only; all 1,439 recovered bytes matched. Restore/run then
started the game and Q returned to the monitor.

```text
B1:8000 0200-0216 0017 C HELLO0200
B1:802F 0200-079E 059F C UCHESS
```

`R 1 UCHESS` runs the saved game. Q returns to the monitor. This restores
the executable and starts a new game; it is not a saved chess-position
checkpoint. The source, original redistribution notice and port credits
remain in the [Microchess example](../examples/beta33/microchess/README.md).

ASM is the only changed utility image. MAINT 2.4, SRAM/WORK/EDU 1.4 and
the saved SRAM CLOCK 1.9 already match the candidate and require no rewrite.
The complete B2 utility/asset bank remains byte-identical to the backup.

## Preserving installation

A fresh backup captured every flash bank and all 128 KiB SPI SRAM twice,
plus EEPROM normal/protected/status, RTC registers/SRAM and application
RAM. The capture verified repeats and restored original application RAM.
The installer was bound to the exact fresh bank hashes and rehearsed in
the CPU model, including actual hash opcodes, stale-preimage refusal,
corrupt-payload refusal and final commit ordering.

Five sectors were updated in order: B3:C, B1:F, B1:E, B3:E and B3:B.
All erase attempts were accounted for. The ASM descriptor was published
only after the new image was verified; monitor validity was committed last.
No B0 or B2 erase was needed. Beta28 A, fixed recovery, resident services,
identity/settings tails and existing saved programs were preserved.
Adding UCHESS programmed erased space without another erase.

All four banks matched the installer target before the game test and the
exact model-predicted post-demo images afterward. Boot
continues to report `Sector B2:8, max 581 tracked erases.`

MAINT 2.4, SRAM/WORK/EDU 1.4 and CLOCK 1.9 passed launch/query/return and
BATCH checks. Error stopping, Escape cancellation and refusal of interactive
ASM inside BATCH were verified. J3 booted beta28 A and returned to the default
beta34 B. Board name 2512 and offset -05:00 remain unchanged.

All 131,072 SPI SRAM bytes match the fresh backup, as do EEPROM normal,
protected and status bytes and RTC SRAM. RTC control/trim, alarms, history
and backup/PF status are preserved; the calendar advanced normally. CLOCK
continues to report trim -12 and backup enabled. Original application RAM
$0200-$64FF (25,344 bytes) was restored with load-only S19, without executing
it, and read back exactly. The restore-needed marker is cleared.

Evidence is under `output/qualification/beta34-2512-2026-10-16/`: `prior/`
contains the fresh backup, `upgrade/` contains the exact installer and model
proofs, and `hardware/` contains live results and readbacks. The installed
