# Beta33 and standalone ASM on 2512

Installation and hardware verification passed. All retained-data comparisons
passed, the complete original application RAM was restored and verified, and
COM4 was closed. The saved HELLO record remains available in flash.

Board 2512 (COM4, 65C02) runs beta33 in monitor B, generation 45
(`0000002D`). Beta28 remains valid in A. J3 selected A successfully and
then returned to the default beta33 B. The isolated branch is
`codex/v2-beta33-asm`; v2.1 remains separate. Beta33 is the intended 2.0
freeze candidate, pending the remaining release gates.

## ASM memory layout

Standalone ASM 0.4 is brought forward from the earlier ASM branch. It runs
from B1:E000-F863, entry E010, using 6,244 bytes of an 8,192-byte two-sector
allocation. The end-of-bank vectors occupy part of the space outside the
ASM image. No additional permanent monitor RAM is reserved.

| RAM while ASM is open | Use |
|---|---|
| $0200-$32FF | Contiguous code/output: 12,544 bytes (12.25 KiB) |
| $3300-$4EFF | Packed source: 7,168 bytes |
| $4F00-$62FF | Symbols: 5,120 bytes, 256 records |
| $6300-$64FF | State and input buffers: 512 bytes |

Default logical origin and physical output both start at $0200. On the
board, ASM filled all 12,544 output bytes with AB, preserved LIST output,
and refused a one-byte overflow. A monitor readback checked every output
byte. Existing protected EDU services at $6500-$66FF remain outside ASM.

The native B2 bundle uses 22,062 of its 22,528 reserved bytes, leaving 466;
the 50-byte increase restricts BATCH's A-command allowlist to exact APPS.
ASM uses its own interactive reader and is refused inside BATCH.

## On-board demonstration

The HELLO source was entered through ASM's numbered editor, assembled to
23 bytes at $0200, inspected and run using G 0200. It calls public RAM
PUTC/HOLD, prints OK and returns to the monitor. The generated program was
stored at B1:8000 with:

```text
S 1 AUTO 0200 0216 HELLO0200
T 1
R 1 HELLO0200 L
R 1 HELLO0200
```

The test zeroed the 23 RAM bytes before Restore, verified their recovery,
then ran the saved program through Restore. S/T/R stores the generated
program; the source editor session is not persisted. Enter
`R 1 HELLO0200` to run the saved example. See the
[source and RAM-variable examples](../examples/beta33/README.md).
