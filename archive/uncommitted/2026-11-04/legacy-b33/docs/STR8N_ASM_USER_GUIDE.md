# STR8-N ASM 0.4 user guide

ASM runs from flash on beta33 and builds W65C02 RAM programs on the board.
At B3>, enter APPS to find it, then ASM. At ASM>, ASM means assemble the source.
The supported 816 host profile is emulation mode; 816 instructions are not added.

## One contiguous code window

| CPU RAM | ASM use |
|---|---|
| $0200-$32FF | User code/output, 12.25 KiB |
| $3300-$4EFF | Source text |
| $4F00-$62FF | Symbols |
| $6300-$64FF | Variables and input buffers |

Source editing does not touch the lower code window. Assembly writes generated
bytes there. Default ORG is $0200, matching the physical output buffer. No
additional permanent RAM reservation exists after leaving ASM.

## Enter, assemble and run

At ASM>, type a decimal line number followed by source. Reusing a number
replaces that line; entering only its number deletes it. Example:

```text
10 ORG $0200
20 LDA #'A'
30 JSR $7E6D
40 JMP $7E67
ASM
DUMP
QUIT
```

At B3>, G 0200 prints A and returns through public RAM HOLD. PUTC at $7E6D
and HOLD at $7E67 work across flash banks. Use the full [HELLO and counter
examples](../examples/beta33/README.md) for Store/Table/Restore.

## Editor commands

| At ASM> | Action |
|---|---|
| number text | Insert or replace a source line |
| number | Delete a line |
| NEW | Start empty source and invalidate output |
| LIST | Display source with line numbers |
| PASTE | Append ordinary source; a line containing only . ends paste |
| ASM | Assemble and report byte count, logical origin and output buffer |
| DUMP | Display generated bytes at their logical addresses |
| S19 | Export S1 data and an S9 entry at the logical origin |
| QUIT | Return to the monitor, leaving generated bytes in RAM |
| ? | Help |

PASTE assigns numbers in steps of ten and suppresses echo while receiving.
Wait for its paste message before sending text. Ctrl-C cancels input or paste.
Backspace and DEL edit the current line. CR, LF and CRLF are accepted. A line
has a 120-character limit; oversized edits are rejected. Invalid paste reports
the first failure and discards subsequent lines through the terminating period.
Earlier valid lines remain. A fresh ASM launch starts a new source session.

Edits invalidate assembled output. Failed assembly prevents DUMP/S19 from
publishing partial output. Source uses packed records, not fixed line slots.
LIST is suitable for host text capture; no persistent source-file command is added.

## Assembly syntax

Mnemonics, commands and symbol names ignore case; quoted strings retain case.
A semicolon starts a comment outside a string. Labels have a trailing colon;
constants use `name = expression`. Names begin with a letter or underscore,
contain letters/digits/underscores, and have at most 15 characters.

Local .name labels/constants belong to the preceding global label. Each global
label starts a scope; a global constant does not. Up to 256 globals and locals
share the symbol table. Forward references are supported for operands; layout
expressions must be known in the first pass. No macro/include/object linker is added.

| Directive | Meaning |
|---|---|
| ORG address[,fill] | Logical origin; later forward gaps use fill, default zero |
| BYTE values | Byte expressions and quoted strings |
| WORD values | Little-endian words |
| TEXT string | Byte/string data |
| FILL count,value | Repeat a byte |
| END | Stop processing source |

A directive may have a leading dot. Expressions support decimal, $hex, %binary,
character literals, symbols, current address *, parentheses, unary + - < >,
and binary + -. Unary < and > select low/high bytes. Nesting is limited to eight
levels. Values are 16 bit; literal overflow and byte/branch range errors are
reported. Strings support the usual n/r/t/0, quote and backslash escapes.

Unresolved direct operands keep an absolute instruction width when available.
Known byte addresses can use zero-page forms. There is no automatic branch
expansion. All 212 documented W65C02 encodings are included; bare BRK emits
its opcode and zero signature byte.

## Origin, storage and limits

Output is always physically at $0200, with a maximum length of 12,544 bytes.
ORG $0200 makes it immediately runnable there after QUIT. For another logical
origin, S19 provides addressed records for loading after QUIT; G does not move
code. Source/symbol/state buffers occupy the upper part of application RAM
only while ASM owns the session. A restored program can overwrite them after
QUIT, using the normal monitor RAM bounds ($64FF with EDU ON, $66FF with EDU OFF).

S stores the RAM range supplied to it. T lists that range. R restores to that
recorded address; L as a suffix restores without running. Thus S/T/R of an
ORG $0200 program uses $0200 and its actual final byte, with no copy step.
ASM is interactive and is refused inside BATCH; APPS remains batchable.
